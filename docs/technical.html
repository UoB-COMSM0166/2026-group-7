✿ Three Core Challenges

Every game hides a handful of design problems that define the project. Here are the three that shaped every technical and creative decision we made on Park Street Survivor.

Challenge 01

Complex State Management & Non-blocking Persistence

The Problem

The engine manages 19 states inside a 60fps render loop. The pause state can be triggered from the room, the story runner, or the endless runner — and without careful handling it was easy to return to the wrong scene on resume. On top of that, writing to localStorage synchronously during gameplay blocked the main thread and caused visible frame drops.

Challenge 02

Node-based Narrative Engine & Dynamic Logic Injection

The Problem

The narrative engine needs to handle branching dialogue and trigger game state changes at specific nodes, without adding overhead to the render loop. Hardcoding script content alongside game logic would make both unmaintainable across five days of story content.

Challenge 03

Procedural Obstacle Scaling Across Modes & Difficulty Levels

The Problem

The obstacle generator had to produce fair, escalating difficulty across five story levels and an endless mode — without feeling random or punishing. Each obstacle type (scooter, puddle, commuter) has different widths, speeds, and lane positions, and the spawning logic needed to guarantee minimum gaps and avoid impossible clusters while still responding to the player's current difficulty setting.

✿ System Architecture

The game is built on a Finite State Machine (FSM) at its core, managing transitions between scenes, player states, and narrative events. All modules communicate through a centralised event bus to keep components decoupled and independently testable.

⚙️

FSM (19 States)

GameState.setState() centralises all side-effects — BGM, UI, scene routing — across 19 heterogeneous states.

💬

Narrative Engine

MVC-separated node-graph system: dialogue_data.js (data), Cutscene.js (logic), DialogueBox (view).

🚧

Obstacle System

Mode-cycle procedural generator with per-type gap enforcement and weighted spawning across 5 difficulty levels.

💾

Save System

SaveSystem.tick() debounced at 3000ms inside the draw loop. Atomic two-phase restore on load via applyAndResume().

🔊

BGM Manager

Centralised audio routing with safe switching — no double-loop, volume sync, and state-driven track selection.

🖼️

p5.js Renderer

HTML5 Canvas via p5.js with layered sprite rendering, parallax scrolling, and weather overlay effects.
